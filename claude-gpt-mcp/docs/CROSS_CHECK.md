# Claude–GPT Bridge (B-2) 설계 — 교차검토 체크리스트

`DESIGN.md`와 이 목록을 함께 다른 AI 또는 검토자에게 전달하면 독립 검토가 가능하다.
각 항목은 "예/아니오 + 근거(문서 섹션 번호)"로 답하도록 요청할 것.

## 전제
- [ ] ChatGPT 로그인 시 구독 사용량으로 처리된다는 근거가 문서에 있는가 (§0.1)
- [ ] `codex mcp-server` 폐기 예고를 반영해 래퍼가 `exec`만 의존하는가 (§0.1, §7)
- [ ] 실제 답변 왕복이 미검증임이 명시되어 있고 구현 1단계에서 확인하는가 (§0.1, §10)

## 구조
- [ ] 도구·코어·외부 계층 사이에 역방향 호출이 없는가 (§1.2)
- [ ] 자식 프로세스 실행 코드가 codex_runner.py 한 곳에만 있는가 (§4.1)
- [ ] codex 경로·모델·타임아웃·허용 폴더·라운드 상한이 config.json에 있는가 (§1.4)
- [ ] 래퍼가 auth.json이나 API 키를 읽거나 쓰지 않는가 (§0.2, §7)
- [ ] 역할 지시문이 스킬 한 곳에서만 관리되고 래퍼가 그것을 읽는가 (§3, §4.2)
- [ ] server.py에 처리 로직이 없고 등록만 하는가 (§1.2)

## 흐름
- [ ] STEP 1~6의 모든 실패 분기에 등급과 반환 메시지가 있는가 (§5)
- [ ] 같은 세션 병렬 호출 시 thread resume이 잠금으로 직렬화되는가 (§4.3, §7)
- [ ] 큰 입력을 파일로 전환하는 임계와 임시 파일 삭제 시점이 있는가 (§4.2, §5)
- [ ] 세션 삭제 시 Codex 쪽 세션도 함께 정리되는가 (§4.3, §7)
- [ ] 토론 라운드 상한과 타임아웃 후 프로세스 종료가 정의되어 있는가 (§4.1, §7)
- [ ] 체크포인트가 STEP 6 완료 후에만 기록되고 STEP 4 전에는 저장하지 않는가 (§5)

## 검증
- [ ] 출력 스키마가 Codex(--output-schema)와 래퍼 양쪽에서 검사되는가 (§6)
- [ ] 사전점검(설치·로그인)이 캐시되어 매 호출마다 느려지지 않는가 (§4.4)
- [ ] GPT 답변이 "참고 의견" 태그로 전달되고 스킬 규칙에도 명시되는가 (§2.3, §3)
- [ ] 한도 도달 문구를 감지해 등급3으로 돌리고 자동 재시도하지 않는가 (§4.1, §8)
- [ ] 잔여 한도를 정확히 알 수 없다는 한계가 문서에 명시되어 있는가 (§6)

## 안전장치
- [ ] 샌드박스가 읽기 전용으로 고정되고 승인 요청이 뜨지 않는가 (§7)
- [ ] allowed_roots 밖 폴더를 넘기면 거부되는가 (§4.4, §7)
- [ ] map.json 저장이 temp→rename→재읽기 방식인가 (§4.3)
- [ ] 로그에 요청ID·thread·소요시간·등급·종료코드가 있고 본문은 기본 미기록인가 (§4.5)

## 실무 리스크
- [ ] Windows에서 codex.cmd 경로·UTF-8 인코딩·stdin 파이프·프로세스 트리 종료가 고려되었는가 (§1.4, §4.1)
- [ ] 로그인 토큰 만료 시 사용자가 무엇을 해야 하는지 메시지에 나오는가 (§8)
- [ ] Codex 업데이트로 명령 옵션이 바뀌면 어떻게 감지·안내하는가 (§7)
- [ ] 경로 A만 쓰는 사용자도 스킬만으로 검산이 가능한가 (§3)
- [ ] Claude 쪽 구독과 ChatGPT 쪽 구독이 각각 차감된다는 점이 명시되어 있는가 (§0.2)

## 검토자에게 요청할 추가 질문
1. 위 항목 중 문서만으로 판단 불가능한 것은 무엇이며, 무엇이 더 필요한가
2. 설계에서 빠졌다고 보는 실패 시나리오는 무엇인가
3. 래퍼 없이 경로 A + 스킬만으로 충분한 경우와 래퍼가 꼭 필요한 경우를 구분해 달라
