# Claude–GPT Bridge 설계 — 교차검토 체크리스트

`DESIGN.md`와 이 목록을 함께 다른 AI 또는 검토자에게 전달하면 독립 검토가 가능하다.
각 항목은 "예/아니오 + 근거(문서의 섹션 번호)"로 답하도록 요청할 것.

## 구조
- [ ] 도구·코어·외부 계층 사이에 역방향 호출이 없는가 (§1.1)
- [ ] API 호출 코드가 gpt_client.py 한 곳에만 있는가 (§3.1)
- [ ] 모델명·단가·한도·경로가 모두 config.json에 있는가 (§1.3)
- [ ] API 키가 config·코드·로그 어디에도 적히지 않는가 (§0, §3.6)
- [ ] server.py에 처리 로직이 없고 등록만 하는가 (§1.1)

## 흐름
- [ ] STEP 1~7의 모든 실패 분기에 등급과 반환 메시지가 정의되어 있는가 (§4)
- [ ] 병렬 도구 호출 시 같은 세션 파일이 잠금으로 보호되는가 (§3.3, §6)
- [ ] 요약 압축 후에도 세션 파일에 원문이 남는가 (§3.3)
- [ ] API 성공 후 저장 전 중단 시 비용이 누락되지 않는가 — pending 예약/확정 (§3.4, §6)
- [ ] 토론 라운드·재시도·파싱 재요청·요약 압축에 상한이 있는가 (§6)
- [ ] 체크포인트가 STEP 7 완료 후에만 기록되는가 (§4)
- [ ] STEP 5 이전에 세션 파일이 수정되지 않는가 (§4)

## 검증
- [ ] 비용 계산이 API 응답값과 독립적으로(토큰 × config 단가) 이뤄지는가 (§3.4, §5)
- [ ] 토큰 추정 오차 허용치(±15%)와 비용 반올림 자리수가 정의되어 있는가 (§3.4, §5)
- [ ] GPT 답변이 Claude에게 "지시"가 아닌 "참고 의견"으로 전달되는가 (§2.4, §5)
- [ ] gpt_cross_check 출력이 항목별 동의/불일치/누락으로 구조화되는가 (§4.2)
- [ ] 구조화 출력 실패 시 GPT 답을 버리지 않고 원문을 돌려주는가 (§4 STEP 6)

## 안전장치
- [ ] 세션 저장이 temp → .bak 회전 → rename → 재읽기 검증 순서인가 (§3.3, §6)
- [ ] 로그에 요청 ID·도구·세션·모델·토큰·소요시간·등급이 있는가 (§3.6)
- [ ] 로그·세션이 stdout으로 나가지 않는가 — MCP 채널 보호 (§3.6)
- [ ] 세션 보관 기간과 자동 정리 규칙이 있는가 (§3.3, §6)
- [ ] 로그 마스킹 대상(키·전화번호·이메일)이 정의되어 있는가 (§3.6)

## 실무 리스크
- [ ] 인터넷 끊김·API 장애 시 Claude 작업이 멈추지 않고 등급3으로 돌아오는가 (§7)
- [ ] config.json이 없거나 깨졌을 때 기본값으로 뜨는지, 등급4로 멈추는지 정해져 있는가 (§1.3)
- [ ] 허용 목록에 없는 모델을 Claude가 요청하면 어떻게 되는가 (§4 STEP 1)
- [ ] Windows 경로·UTF-8 인코딩·stdio 버퍼링이 고려되었는가 (구현 시 확인 필요)
- [ ] 서버 시작 시 남은 pending 사용량이 예산에 반영되는가 (§3.4)
- [ ] 모델명·단가가 "구현 시 확인" 항목으로 남아 있음을 검토자가 인지했는가 (§0)

## 검토자에게 요청할 추가 질문
1. 위 항목 중 문서만으로 판단 불가능한 것은 무엇이며, 무엇이 더 필요한가
2. 설계에서 빠졌다고 보는 실패 시나리오는 무엇인가
3. 6개 도구 중 통합하거나 분리해야 할 것이 있는가
